# Security and privacy

Report a vulnerability privately through the repository's security reporting interface when available. Do not attach an auth file, API Key, Cookie, complete debug trace or unredacted task archive to a public issue. A minimized reproduction with fake credentials is preferred.

## What the app reads

Codex task titles, working directories, turn metadata, whitelisted routing events, response model fields/headers and request diagnostic metadata; enabled providers' quota/balance metadata; optional device-local token/credit records. SQLite connections are read-only. Sources are not rewritten.

The optional desktop observer uses a same-user Unix socket with a non-writable parent directory, validates the peer UID and the running OpenAI-signed router, caps frames at 16 MiB and subscriptions at 40, and never handles task execution or approval requests. State frames can transiently contain task contents in memory; only typed model routing items at known turn paths are retained. It does not recursively scan tool output or model text. Revision gaps discard identity mappings until a fresh snapshot arrives. This desktop IPC is an internal protocol and may change with client updates.

The capture launcher refuses to close or replace a running Codex / ChatGPT client. It verifies the installed client signature and supplies a process-local RUST_LOG setting only after an explicit button click. The default uses core info logging. The separately enabled experimental trace mode may cause Codex itself to retain raw task contents in its own logs and adds overhead; this is disclosed in the UI. Model Lens still retains only whitelisted metadata. A normal relaunch restores the client default. No bundle, Codex configuration, system proxy, trust store or global environment is changed.

Saved task history contains task titles and paths. Even though the app excludes prompt/answer bodies and authorization headers from its evidence projection, an exported archive can still reveal private project information. Review it before sharing.

## Authentication boundaries

Manual accounts use the macOS Keychain and a random account UUID. A local Codex account uses its file or known Keychain authentication format. Before invoking its CLI, the app verifies OpenAI's signing identity. It copies login material to an owner-only temporary home to isolate configuration, hooks and MCP connections, removes that home afterward, and can clean stale owned runs after a crash. It never updates the original login file. Abnormally abandoned files may remain until the next account read or probe; the directory is restricted to its owner.

Incoming metadata is capped; commands have deadlines and cancellation; remote redirects are rejected; web accounts are workspace-scoped. Local Antigravity TLS acceptance is restricted to `127.0.0.1` and a port obtained from the same-user language server inside the signed installed Google app. It is never applied to remote HTTPS.

WorkBuddy encrypted authentication is not decrypted. Its fallback projects only recorded request credits from the local database. Browser credentials are not extracted; OpenCode Cookie accounts require an explicit manual value supplied by the user.

## Model identity

A server model field is a reported identity, not a cryptographic proof of model weights. Local logs and imported files can be altered. An independent probe describes only that probe and is not associated with a desktop task by timestamp. Missing fields, ambiguous associations and conflicting probe fields remain unconfirmed.

## Outbound connections

Only an explicitly opened/refreshed enabled provider is fetched. Expected remote hosts are `chatgpt.com`/OpenAI through the verified official CLI, `api.deepseek.com`, `opencode.ai`, and recognized official WorkBuddy billing hosts. Antigravity uses the signed Google local language server, with the installed helper contacting its official Google endpoints for quota and temporary token refresh when a background query is needed. No app telemetry, analytics SDK, automatic update downloader or background model-generating request is included. The optional network component is downloaded only after the explicit setup button is clicked.

Public status reads use ephemeral HTTPS sessions without account cookies, authentication headers, or URL credential storage. Responses are limited to 2 MiB, redirects are refused and normal system certificate validation is retained. Unknown or unsupported component coverage is never projected as operational. Codex reset-credit reads retain only the available count and nearest expiry; opaque redemption IDs are dropped and no reset-consumption method is invoked.

## Optional network capture

The explicitly started capture session listens only on `127.0.0.1`, forwards to the official ChatGPT host with standard upstream TLS validation, and supplies a temporary local CA and backend origin only to the launched client. The root CA signs a separate CA:FALSE server certificate with serverAuth and loopback SAN; the root itself is never used as a TLS end-entity. Before desktop launch, an isolated signed Codex CLI must successfully read account rate limits through the same connection; failure stops the proxy and leaves the desktop client unopened. It does not install a trusted certificate or change system proxy settings, the original Codex configuration, or authentication. The installed desktop client's internal `CODEX_APP_SERVER_CHATGPT_BASE_URL` interface and Codex custom-CA support are version-dependent. Unsupported clients or missing response identity remain unconfirmed.

This proxy decrypts and forwards the selected client's API traffic in memory. Authentication and task contents therefore pass through the optional helper. The observer saves only explicit task/turn identifiers, server response model names, whitelisted model headers, response IDs and observation timestamps. Client request models, anonymous prewarm responses, conflicting identities and arbitrary output text cannot become server evidence. No flow archive is written; WebSocket history is trimmed and metadata buffers are capped. A fixed record limit prevents unbounded capture output. The helper checks the owning process every two seconds and stops if it has disappeared. Normal cancellation stops only the owned helper and removes temporary certificate keys. Abrupt termination can leave private certificate directories for later removal; they are inside an owner-only app directory.

The optional mitmproxy arm64 archive is pinned to version 12.2.3 and a fixed SHA-256 before extraction or execution. Download redirects are allowed only on the same official HTTPS download host. This upstream archive's package signatures fail validation; after archive integrity verification, only the app-owned copy is made writable and signed ad hoc with the original entitlements/runtime flags, then code integrity is checked. This is not Developer ID authenticity verification or notarization. Its provenance is established by the pinned official download, not by a new publisher certificate. The original installed agents and system security settings are unchanged. The base app does not bundle this executable.

When Antigravity is closed, a verified Google-signed helper may run briefly in a fresh owner-only temporary directory. It receives a private copy of the supported standalone OAuth file and refreshes only that copy. No original auth, configuration or application data is rewritten. This is a quota request, not a model generation. The private copy and owned helper are removed on completion/cancellation. A crash can leave the restricted temporary directory; do not share temporary capture/query folders.

Public RSS/Atom parsing rejects DTD/entity declarations, disables external entity resolution, limits depth/entry counts/response size, renders text without HTML, and only exposes HTTPS links on the official provider status host. OpenAI status now covers all public components. Google status explicitly separates the official Gemini API / AI Studio anonymous incident history from all public Google Cloud incidents; neither is labeled as a dedicated Antigravity component. The Gemini query uses an empty request and a short-lived public client identifier fetched from the official status HTML, never user OAuth, cookies, personal API keys or hardcoded credentials. Redirects are rejected and response sizes are capped. Unavailable status sources and unsupported metrics are hidden. A feed with no unresolved incident is not proof that every service is healthy.

Capture provenance is assigned by the scanner source, not imported JSON fields. NetworkEvidence is reserved for new app captures; older app-generated network-models-UUID files remain recognizable beside manual imports. Manual imports carry imported_from and use evidence-hash names. These labels describe provenance, not authenticated local storage. They do not prove server weights and are not an integrity boundary against an attacker who can modify this user’s files.
